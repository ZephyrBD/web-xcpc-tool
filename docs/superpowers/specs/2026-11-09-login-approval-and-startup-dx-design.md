# 设计：登录审批 + 启动体验修复（2026-11-09）

## 背景
比赛开始后登录时段关闭，迟到队伍无法登录。需求：队伍输入队伍码后进入「等待管理员同意」状态，管理端审批后即可登录。同时修复一批启动体验问题。

## 1. 登录审批（核心功能）

**行为**
- 登录时段外提交队伍码：服务端先校验队伍码正确（错误码仍报「队伍码无效」），正确则创建一条 `pending` 审批请求（队伍 icpcId、队伍名、队伍码、时间、IP），返回「等待管理员同意」。
- 队伍侧 verify 页轮询（约 5s）该请求状态；管理员同意后轮询拿到结果，**自动签发 token 跳转反代**，无需重输队伍码。
- 管理端：**队伍码页改名「认证管理」**，内新增「登录审批」卡片：待审批列表（队伍名 / 队伍码 / 申请时间 / IP）+ 同意 / 拒绝按钮；审批动作走 SSE 实时推送队伍侧。
- 语义：同意 = **当次有效**——仅为该次登录签发 token（且不受时段限制），不做持久豁免；队伍退出/Token 过期后再登录仍需重新审批。拒绝 = 请求关闭，队伍可重新申请。时段本来开着时不产生审批请求。

**存储**：`data/login-requests.json`（审批请求及状态），沿用 JsonStore 模式，无数据库红线不变。同意后的 token 本身即凭证，无需额外豁免存储。

## 2. 启动日志重写（旧项目名 + 信息不清）

`index.ts` 启动横幅改为多行清晰输出：

```
Web XCPC Tool v1.0.0 (abc1234)
  服务地址    http://localhost:8080/wxt
  管理台      http://localhost:8080/wxt/admin  (用户名: admin)
  管理密码    <当前密码>            ← 每次启动都打印（见 3）
  DOMjudge    https://dj.example.com
  气球赛题ID  contest123
```
去掉 `cuitxcpctool` 旧名。DOMjudge 未连通/配置不全时给出明确一行警告而非静默。

## 3. 管理员密码：首次随机生成、每次启动打印

- 现状：`passwordHash` 默认为空 → 管理台登录直接不可用，密码只能靠手工改配置。
- 改为：首次启动 `passwordHash` 为空时随机生成密码（可读字符集，16 位），bcrypt 哈希存配置，**明文密码持久化在 `data/settings.json` 的 `admin.password` 字段**（文件已 gitignore、本地磁盘），每次启动从该字段读取打印。设置页改密码时同步更新明文字段（改密后日志下次启动打印新值）。

## 4. 气球空 contestId 刷屏报错

- 现状：`balloon.contestId` 为空时轮询照样跑，`contests//problems` 每次刷三条报错。这不是 baseUrl 多斜杠（client 已剥尾斜杠），是赛题 ID 为空拼出 `//`。
- 改为：`contestId` 为空时 BalloonService 不启动轮询，启动日志一行「气球联动未启用：未配置赛题 ID（设置 → 气球）」。

## 5. URL 多斜杠防御

- `DjClient` 构造时已 `replace(/\/+$/, "")` 剥尾斜杠（client.ts:147）；再检查配置读取/反代处对 baseUrl 的拼接，统一归一化，杜绝 `https://dj.example.com//api/...`。

## 非目标
- 不做审批请求自动过期（管理员手动处理）；不做多管理员审批流。
- 不改 DOMjudge 侧任何配置要求。

## 验证
- server：审批流（时段外提交→pending→同意→仅当次 token 生效→拒绝可重申）、时段内不产生请求、密码生成/打印、contestId 空不轮询。
- admin：认证管理页改名 + 审批卡片交互、轮询页文案。
